# يلا توكتوك — Yalla Toktok

موديول ويب عربي لحجز التوكتوك والتفاوض على سعر الرحلة، بواجهة عميل ودريفر ولوجو توكتوك. يعمل على الموبايل والكمبيوتر. هذه نسخة أولى عملية (MVP) بسيرفر وقاعدة بيانات، وليست تطبيق Android/iOS منشورًا أو منصة نقل تجارية مكتملة الاعتمادات.

## تحديث الواجهة حسب المرجع

الواجهة أصبحت أصفر وأسود وأبيض، بلوجو أمامي للتوكتوك قريب من المرجع، وكروت «منين؟ / إلى أين؟»، وزر «اطلب توكتوكك»، وتبويب دعم مستقل. بقيت آلية الدخول عميل/دريفر ووظائف الرحلات كما هي. الشكل مستوحى من المرجع وليس نسخة مطابقة بكسلًا ببكسل. لم نضف أرقام دعم أو صور سائقين أو أزمنة وصول وهمية، ونموذج الطلب نيابة عن شخص آخر المعروض في المرجع غير منفذ بهذه النسخة.

للاستضافة المقترحة وشرح حدود الأمان افتح [DEPLOY_RENDER.md](DEPLOY_RENDER.md). لم تُنشر هذه النسخة على أي خدمة.

## الموجود في المشروع

| الجزء | المميزات المنفذة |
|---|---|
| الدخول | اختيار عميل / دريفر، إنشاء حساب، رقم هاتف وكلمة مرور، تسجيل خروج |
| العميل | مكان الركوب والوجهة، GPS اختياري، اقتراح سعر، مقارنة عروض السائقين، قبول عرض، إلغاء قبل بدء الرحلة |
| الدريفر | حساب يخضع لاعتماد الإدارة، متاح / غير متاح، تقديم وتعديل عرض السعر، الوصول، بدء بكود العميل، إنهاء الرحلة |
| الرحلة | تحديث كل 3 ثوانٍ أثناء فتح الصفحة، مشاركة موقع الدريفر بإذنه، اتصال هاتفي، رسائل، مشاركة تفاصيل الرحلة كنص |
| بعد الرحلة | تقييم متبادل، سجل رحلات، مجموع قيمة الرحلات المكتملة، بلاغات للإدارة |
| الإدارة | اعتماد السائقين أو إيقاف استقبالهم، مشاهدة الرحلات والبلاغات والحسابات |
| البيانات | SQLite على السيرفر، كلمات مرور مجزّأة، جلسات انتهاء 7 أيام، تحقق الصلاحيات، حجز ذري لمنع ازدواج السائق |
| المعاينة | وضع تجريبي منفصل ببيانات أمثلة، بدون حسابات أو حجز حقيقي أو حفظ دائم |

الدفع الحالي كاش فقط. الإحصائيات مالية وصفية لقيمة الرحلات، وليست محفظة إلكترونية أو إثباتًا آليًا لاستلام المال.

## 1. التشغيل السريع على جهازك

ثبّت Python 3.12 أو أحدث. على Windows شغّل `start.bat`، ثم افتح:

http://127.0.0.1:8080

أو من الطرفية داخل مجلد المشروع:

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate
python -m pip install -r requirements.txt
python server.py
```

سيرفر `python server.py` للتطوير على جهازك فقط. للتشغيل المستضاف استخدم Docker أو Gunicorn الموضحين لاحقًا.

لا توجد كلمات مرور جاهزة أو حسابات إدارة افتراضية.

## 2. إنشاء الأدمن واعتماد السائق

افتح طرفية ثانية داخل المشروع، وفعّل البيئة الافتراضية، ثم:

```bash
python server.py --create-admin
```

أدخل رقم الهاتف بكود الدولة وكلمة مرور من 12 حرفًا على الأقل. سجّل الدخول من تبويب **عميل** بهذه البيانات؛ النظام يتعرف على دور الأدمن ويفتح لوحة الإدارة تلقائيًا. الأدمن غير قابل للتسجيل من الواجهة العامة.

1. أنشئ حساب عميل من الواجهة.
2. من متصفح آخر أو نافذة خاصة أنشئ حساب دريفر برقم مختلف.
3. افتح لوحة الأدمن واضغط «اعتماد السائق» بعد مراجعة بياناته خارج النظام.
4. في حساب الدريفر فعّل استقبال الطلبات.
5. اطلب رحلة من حساب العميل، ثم قدّم عرضًا من حساب الدريفر.
6. العميل يختار العرض. الدريفر يؤكد الوصول، ثم يدخل كود العميل لبدء الرحلة.
7. أنهِ الرحلة وسجّل التقييم من «رحلاتي».

## 3. الرفع على GitHub

أنشئ مستودعًا باسم `yalla-toktok` وارفع **محتويات هذا المجلد**، بما فيها `.github` و`web` و`server.py`، إلى الجذر. لا ترفع المجلد المضغوط وحده. الملفات الحساسة وقاعدة البيانات مستبعدة في `.gitignore`.

يمكن رفع الملفات بالمتصفح، أو باستخدام Git:

```bash
git init
git add .
git commit -m "Initial Yalla Toktok module"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/yalla-toktok.git
git push -u origin main
```

استبدل `YOUR_USERNAME` باسم حسابك. هذه الحزمة لم تُرفع إلى حساب GitHub نيابة عنك.

### نشر الواجهة على GitHub Pages

في المستودع: **Settings → Pages → Source: GitHub Actions**. ثم شغّل workflow المرفق من **Actions** أو ادفع تعديلًا إلى `main`. سيرفع محتويات `web`.

بدون سيرفر: الواجهة والمعاينة التجريبية تعملان، لكن تسجيل الحسابات والربط بين أجهزة العملاء والسائقين يحتاجان API مستضافًا.

مع السيرفر: عدّل `web/config.js`:

```javascript
window.YALLA_CONFIG = {
  apiBase: "https://api.YOUR_DOMAIN.com"
};
```

ضع عنوان السيرفر الحقيقي بدون `/api` وبدون شرطة أخيرة. على السيرفر، اضبط متغير البيئة `ALLOWED_ORIGINS` على أصل واجهة Pages (بدون مسار المستودع):

```text
ALLOWED_ORIGINS=https://YOUR_USERNAME.github.io
```

GitHub Pages يستضيف HTML/CSS/JavaScript، ولا يشغّل سيرفر Python أو SQLite. مرجع: [GitHub Pages الرسمي](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

## 4. استضافة السيرفر

الاختيار الأسهل في البنية: استضف المشروع كله على سيرفر واحد يدعم Python أو Docker؛ سيقدم السيرفر الواجهة تلقائيًا، ولا تحتاج GitHub Pages أو تعديل `apiBase`.

### Docker

```bash
docker compose up -d --build
docker compose exec app python server.py --create-admin
```

الخدمة في `compose.yaml` مربوطة بـ `127.0.0.1:8080` لتوضع خلف reverse proxy يدعم HTTPS. قاعدة البيانات محفوظة في volume باسم `toktok-data`.

### Gunicorn (Linux)

```bash
python -m pip install -r requirements.txt
python -m gunicorn --bind 0.0.0.0:8080 --workers 2 --threads 4 server:app
```

متغيرات البيئة:

| المتغير | القيمة |
|---|---|
| `DATABASE_PATH` | مسار ملف SQLite على قرص دائم؛ الافتراضي `data/toktok.sqlite` |
| `ALLOWED_ORIGINS` | أصول المواقع المسموحة، تفصل بفاصلة؛ مثل `https://YOUR_DOMAIN.com,https://YOUR_USERNAME.github.io` |
| `PORT` | المنفذ داخل Docker أو عند التشغيل المحلي؛ الافتراضي 8080 |

عند استخدام HTTPS عبر reverse proxy أضف **أصل الموقع نفسه** أيضًا إلى `ALLOWED_ORIGINS`، لأن التطبيق لا يثق في forwarded headers تلقائيًا. لا تضع `*`.

SQLite يحتاج قرصًا دائمًا مشتركًا بين workers على نفس السيرفر. لا تشغّل نسخ التطبيق على عدة أجهزة بقواعد بيانات منفصلة. استخدم قاعدة بيانات مشتركة مثل PostgreSQL عند التوسع، بعد تعديل طبقة البيانات.

مرجع إعداد التشغيل: [Flask — النشر للإنتاج](https://flask.palletsprojects.com/en/stable/deploying/).

## الخرائط والموقع

- الخريطة التفاعلية المضمنة من OpenStreetMap تعرض علامة واحدة: مكان الركوب، أو آخر موقع شاركه السائق. تحتاج إنترنت.
- وصف مكان الركوب والوجهة نصي. الإحداثيات اختيارية ويمكن إدخالها يدويًا؛ لا يوجد بحث آلي عن العناوين أو حساب مسافة الطريق / زمن الوصول.
- عند توفير إحداثيات الوجهة، يظهر رابط الاتجاهات في Google Maps.
- مشاركة GPS من زر داخل الرحلة، وتعمل أثناء فتح الصفحة ومنح الإذن. تحتاج HTTPS أو localhost. ليست تتبعًا مضمونًا في الخلفية.
- عند عدم وجود موقع اختاره المستخدم، تظهر منطقة القاهرة كمركز خريطة افتراضي، ولا تُدّعى أنها موقعه.
- ظهور السائق «متاح» يعتمد على المفتاح الذي يختاره، وليس قياس اتصال موثوقًا؛ لا يوجد heartbeat أو انتهاء تلقائي للعروض. تحقق من تواجده قبل اعتماد تشغيل عام.
- الطلبات المعروضة حاليًا ليست محددة بنطاق جغرافي. أضف مناطق خدمة وفلترة مسافة قبل نشر المنصة في أكثر من منطقة.

مراجع: [OpenStreetMap](https://www.openstreetmap.org/copyright)، [MDN Geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API).

## حدود النسخة وما يلزم قبل الإطلاق التجاري

هذه أساس عملي للتطوير والتجربة، ولم تُختبر تحت حمل إنتاجي أو على أسطول حقيقي. لا تتضمن:

- SMS/OTP، إثبات ملكية رقم الهاتف، استعادة كلمة المرور، رفع وفحص وثائق السائق؛ أرقام الهواتف تُسجل كما يكتبها المستخدم ولا توحَّد صيغها تلقائيًا.
- بوابة دفع أو محفظة أو عمولات وتسويات مالية وكوبونات.
- Push Notifications أو تطبيق هاتف Native أو تتبع خلفية أو مسارات دقيقة أو geofencing.
- دعم مباشر أو خدمة طوارئ أو زر يرسل استغاثة. البلاغ يُحفظ للإدارة فقط.
- سياسة تشغيل قانونية جاهزة، تحقق تراخيص، إدارة حذف البيانات من الواجهة، جدولة نسخ احتياطية، أو إغلاق البلاغات؛ يجب أن يحدد المشغّل الإجراءات والمراجعات المناسبة قبل إطلاق حقيقي.

الهوية المرئية جاهزة، ولكن بيانات تواصل المشغّل وسياسة الاحتفاظ بالبيانات يجب إضافتها قبل فتح التسجيل للجمهور. حدود المعدل الحالية مخصصة للدخول والتسجيل حسب عنوان الاتصال؛ اضبط حدود الشبكة على reverse proxy عند النشر. لا تسجل كلمات المرور أو رموز الجلسات في السجلات.
